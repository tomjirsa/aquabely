# Aquabely U12 Refactor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the single-format L3 app with a multi-category app that imports L3 and U12 result PDFs, shares athletes across levels, keeps every judge mark, and presents the results in a restyled Streamlit UI behind login.

**Architecture:** One parser module per result format, chosen by a header-based registry, all producing shared dataclasses. Validation runs before a single-transaction import into a fresh SQLite schema. Query and UI code read only from the database and the shared models, never from format-specific code.

**Tech Stack:** Python 3.12, Streamlit (>=1.35), pdfplumber, pandas, plotly, sqlite3 (stdlib), pytest.

**Spec:** `docs/superpowers/specs/2026-11-21-u12-refactor-design.md`

## Global Constraints

- Python 3.12; dependencies pinned as in `requirements.txt`. Add none without a task that needs it.
- The database path comes from `AQUABELY_DB` (default `~/aquabely.db`). The schema is created fresh; no migration.
- Sample PDFs in `data/` are git-ignored and must never be committed. Tests that need them skip with a message when the files are absent.
- Athlete identity is `(name, club_id)`. Names are stored as extracted; there is no correction step.
- Level codes are `L3` and `U12`. "Beginner L3" and "L3 FIG" both map to `L3`.
- Judge counts are per competition (`judges_per_figure`), never per category.
- Every commit message ends with `Co-Authored-By: Claude Haiku 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Re-importing the same file is refused and writes no rows. Test in Task 8.
2. A PDF matching no format, or matching two, is rejected with a clear message and nothing is written. Test in Task 5 and Task 8.
3. An athlete who competes in both L3 and U12 is one `athletes` row with two `results` rows. Test in Task 8.
4. Names with diacritics (for example `SCHOVÁ`) are stored and displayed unchanged. Test in Task 6.
5. A non-zero penalty is stored and kept in the total. Test in Task 3 (L3) and Task 6 (U12).

### Task 4: Score-rule check and structural validation

**Files:**
- Create: `parser/validate.py`
- Test: `tests/test_validate.py`

**Interfaces:**
- Consumes: `ParsedCompetition` (Task 1).
- Produces: `validate(comp: ParsedCompetition) -> ValidationReport` with `errors: list[str]` (rejects the file) and `warnings: list[str]` (shown, does not block).

Checks:
- Error: a result's `figure_results` count differs from the number of figures.
- Error: any `judge_scores` length differs from `judges_per_figure`.
- Error: ranks are not consistent with total score (a higher total must not have a worse rank).
- Warning: `score` differs from `mean(judge_scores) × difficulty` by more than 0.01 when `difficulty` is set. The rule is not yet confirmed (see the spec's Known Problems).

### Task 8: Import transaction (idempotent, all-or-nothing)

**Files:**
- Create: `db/importer.py`
- Test: `tests/test_importer.py`

**Interfaces:**
- Consumes: `ParsedCompetition` (Task 1), `validate` (Task 4), schema (Task 2).
- Produces: `import_competition(conn, comp: ParsedCompetition, sha256: str, filename: str) -> int` returning the new `competitions.id`. Raises `DuplicateImportError` when `sha256` already exists, and `ValidationFailed(errors: list[str])` when validation has errors. Each attempt, successful or not, writes one `imports` row. Successful writes and the `imports` row for a successful attempt commit together. Failed attempts write only their `imports` row, with status `rejected` and the error text.

Write order inside one transaction: `clubs` (upsert by name), `athletes` (upsert by `(name, club_id)`), `competitions`, `categories` (lookup by `comp.level_code`), `competition_categories`, `figures`, `results` (with `club_id` as entered for that event), `figure_results`.

- [ ] **Step 1: Write the failing test**

# tests/test_importer.py
import sqlite3
import pytest
from db.database import init_schema
from db.importer import import_competition, DuplicateImportError, ValidationFailed
from parser.models import FigureDef, FigureResult, ParsedCompetition, ParsedResult


@pytest.fixture
def conn():
    c = sqlite3.connect(":memory:")
    c.execute("PRAGMA foreign_keys = ON")
    init_schema(c)

def make(level="L3", name="A", club="C", judges=5):
    fr = FigureResult("F1", [5.0] * judges, 5.0, 0.0)
    r = ParsedResult(1, 1, name, club, "CZE", 2016, 50.0, 0.0, 0.0, [fr])

def test_import_writes_rows(conn):

    assert conn.execute("SELECT COUNT(*) FROM results").fetchone()[0] == 1
    assert cid == 1

        import_competition(conn, make(), sha256="h1", filename="a.pdf")
